# Full code review — 2026-10-25 / 1.0.0.3

Reviewed production code: Plugin, Configuration/ConfigurationPersistence, ListingService, ListingModel, ListingGamePort, RecallRun, GamePort, InventoryScopes, NativeMenu/NativeButton, RetainerAgentState, Localization/LocalizedFonts, and the shared tab integration. Reviewed existing tests and release metadata. No game process, production configuration or installed DLL was modified.

## Findings fixed

1. **Price learning accepted an offer change without source confirmation.** `ConfirmedPriceItem` previously accepted any single offer at the captured quantity/price, including an existing offer's price edit. New tests fail on the previous implementation. It now requires exactly one added offer, unchanged existing offers, and the exact captured inventory slot's quantity decrement. Player/retainer/armoury sources remain supported and NQ/HQ still share the stored base-item price.
2. **Manual price capture used the last shortcut's inventory scope.** `CaptureSale` called `port.Read()` with mutable `FromRetainer`, initially false. It now reads the actual sale agent's source inventory, captures its exact Stock record, and observes that inventory scope until confirmation. Player/retainer reads are cached separately within each observation tick, at most once per scope for the capture batch. This wiring was source-reviewed; native agent timing remains unverified in-game. Synthetic rules verify retainer source acceptance and wrong inventory/slot rejection.
3. **Version 0.1 settings were rejected as corrupted by 1.0.0.2.** The actual v0.1.0.0 tag used Version=1 with only Player and Retainer. A synthetic equivalent reproduced the rejection. That exact older feature set now loads with listing defaults while preserving button settings. Partially missing modern settings remain invalid. No migration was run on user data.
4. **Native boundary guards were incomplete.** Added null checks for the framework, inventory context agent, AtkValues, and menu renderer owner; callbacks now reject absent/unready/hidden addons and invalid argument counts. This is defensive hardening, not evidence of a newly reproduced game crash. Synthetic absent/unready callback cases pass.
5. **A failed price-observation batch could remain pending and throw again every frame.** The error path now clears pending captures when stopping. No automatic confirmation retries were added.

## Verification

- Release rebuild: zero warnings and zero errors.
- 155 managed listing/recall/localization checks; 19 synthetic native boundary checks; 26 persistence checks; 29 offscreen UI/lifecycle checks: 229 total.
- Newly reproduced failures: offer-only price learning and recall-only v0.1 configuration loading. Both regressions now pass.
- Persistence behavior remains: 600 changes -> one 434-byte commit; ten unchanged periods -> zero writes; three injected failures -> zero commits and 1,296 temporary payload bytes. These are logical application bytes, not physical SSD writes.
- Shared StandardPluginTabs remains byte-identical to canonical (SHA-256 062372ECBF0030427BCDFE471592C6691CE3A3D3F8835A7438EA95C7763B25E9).
- No new network or database requests. No raw packet sending, inventory-memory writes, or change to successful confirmation dispatch. Source/target validation remains conservative; ambiguous updates stop or do not teach a price.

## Remaining limits

This review does not establish that the plugin is bug-free. Actual current-game native offsets, callback contracts, other-plugin interference, delayed server updates, manual retainer capture timing, and lifecycle timing require live acceptance. The previously reported full-armoury retrieval stop remains unresolved/unverified; no claim of a fix is made. Existing native crash regression tests pass, but they cannot guarantee native safety in all game states.

Publication follows the parent AGENTS.md continuous update/publication authorization, using the existing repository and custom index. Version 1.0.0.3 is a new release, not an overwrite of 1.0.0.2.
